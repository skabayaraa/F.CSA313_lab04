# F.CSA313 Lab 04 – JUnit 5 Unit Testing

**Оюутан:** Энхсаруул Эрдэнэбаяр
**Хичээл:** F.CSA313
**Project:** `lab04-junit`

## Ашигласан орчин

* Java: OpenJDK 17
* Maven: Apache Maven
* JUnit Jupiter: 5.10.2
* Maven Surefire Plugin: 3.2.5
* OS: Ubuntu / WSL2

## Лабораторийн ажлын тухай

Энэ лабораторийн ажлаар Maven ашиглан JUnit 5 тестийн орчин үүсгэж, `GradeCalculator` классын үйлдлүүдийг unit test-ээр шалгасан. Эхлээд Maven project-оо тохируулж, JUnit Jupiter 5.10.2 dependency болон Java 17 compiler тохиргоог хийсэн. `GradeCalculator` класс дотор оюутны оноонд үндэслэн үсгэн дүн гаргах болон нийт оноо тооцоолох хоёр үндсэн үйлдлийг хэрэгжүүлсэн. Үсгэн дүнгийн хувьд 90-ээс дээш болон тэнцүү оноог A, 80-89 оноог B, 70-79 оноог C, 60-69 оноог D, 60-аас бага оноог F гэж тооцсон. Мөн 0-100-ийн хязгаараас гарсан оноо оруулсан үед `IllegalArgumentException` үүсгэхээр шалгасан.

Тестүүдээ бичихдээ Arrange, Act, Assert гэсэн бүтэц ашигласан. Boundary value testing хийхдээ 90, 89.99, 60, 59.99, 0 болон 100 зэрэг зааг утгуудыг тусгайлан шалгасан. Мөн буруу утгууд болох -1 болон 101 оноо оруулах үед exception зөв үүсэж байгаа эсэхийг `assertThrows` ашиглан шалгасан. `totalScore` method-ийн хувьд ирц, лаборатори, quiz болон шалгалтын оноонуудын зөвшөөрөгдөх хязгаарыг шалгасан. Олон төрлийн утгыг давтаж шалгахын тулд JUnit 5-ийн `@ParameterizedTest` болон `@CsvSource` ашигласан. Ингэснээр ижил төрлийн тестийн кодыг олон удаа давтахгүйгээр өөр өөр оролтын утгуудаар шалгах боломжтой болсон.

Нийт **39 test case** ажиллуулж, бүх тест амжилттай болсон.

```text
Tests run: 39, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

## Mutation Testing

Тестүүд маань зөвхөн зөв ажиллаж байгааг шалгахаас гадна алдааг илрүүлж чадаж байгаа эсэхийг шалгахын тулд mutation testing хийсэн. Үүний тулд `GradeCalculator` классын `score >= 90` нөхцөлийг түр хугацаанд `score > 90` болгон өөрчилсөн. Энэ өөрчлөлтийн дараа 90 оноо A биш B болж буруу тооцогдсон. Boundary test-ийн 90 онооны тест энэ өөрчлөлтийг илрүүлж, тест амжилтгүй болсон.

```text
Tests run: 39, Failures: 1, Errors: 0, Skipped: 0
BUILD FAILURE
```

Алдааны хэсэгт:

```text
expected: <A> but was: <B>
```

гэж гарсан. Энэ нь 90 гэсэн зааг утгыг тестүүд зөв шалгаж байгааг харуулсан. Mutation test дууссаны дараа кодын нөхцөлийг буцааж `score >= 90` болгож, бүх тестийг дахин ажиллуулахад 39 тест бүгд амжилттай болсон.

## Test ажиллуулах

```bash
mvn clean test
```

Үр дүнг `results/mvn-test.txt` файлд хадгалсан.

Mutation test-ийн үр дүнг:

```text
results/mvn-test-mutant.txt
```

файлд хадгалсан.

## Дүгнэлт

Энэ лабораторийн ажлаар JUnit 5 ашиглан unit test бичих, boundary value testing хийх, exception шалгах болон parameterized test ашиглах талаар дадлага хийсэн. Мөн mutation testing хийж, бичсэн тестүүд маань кодын жижиг өөрчлөлтөөс үүссэн алдааг илрүүлж чадаж байгаа эсэхийг шалгасан. Maven ашиглан бүх тестийг ажиллуулж, тестийн үр дүнг тусдаа файлд хадгалсан. Ажлын явцад Java compiler-ийн тохиргооноос үүссэн `source 7` алдааг засаж Java 17 дээр тестүүдийг амжилттай ажиллуулсан.
