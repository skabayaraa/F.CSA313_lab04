## Лабораторийн ажлын тухай

Энэ лабораторийн ажлаар Maven ашиглан JUnit 5 тестийн орчин үүсгэж, `GradeCalculator` классын үйлдлүүдийг unit test-ээр шалгасан. Эхлээд лабораторийн шаардлагын дагуу Maven project-г орчинд нь тохируулж, JUnit Jupiter 5.10.2 dependency болон Java 17 compiler тохиргоог pom.xml файл дээр гараар хийсэн. `GradeCalculator` класс дотор оюутны оноонд үндэслэн үсгэн дүн гаргах болон нийт оноо тооцоолох хоёр үндсэн үйлдлийг багтаасан. Үсгэн дүнгийн хувьд 90-ээс дээш болон тэнцүү оноог A, 80-89 оноог B, 70-79 оноог C, 60-69 оноог D, 60-аас бага оноог F гэж тооцсон. Мөн 0-100-ийн хязгаараас гарсан оноо оруулсан үед `IllegalArgumentException` үүсгэхээр тохируулсан.

Тестүүдээ бичихдээ Arrange, Act, Assert гэсэн бүтэц ашигласан. Boundary value testing хийхдээ 'GradeCalculatorTest.java' дотор 90, 89.99, 60, 59.99, 0 болон 100 зэрэг зааг утгуудыг оруулж, зөв үсгэн үнэлгээ өгч буй эсэхийг онцлон шалгасан. Мөн буруу утгууд болох -1 болон 101 оноо оруулах үед IllegalArgumentException гарч байгаа эсэхийг `assertThrows` ашиглан шалгасан. `totalScore` method-ийн хувьд ирц, лаборатори, quiz болон шалгалтын оноонуудын зөвшөөрөгдөх хязгаарыг шалгасан. Олон төрлийн утгыг давтаж шалгахын тулд JUnit 5-ийн `@ParameterizedTest` болон `@CsvSource` ашигласан. Ингэснээр ижил төрлийн тестийн кодыг олон удаа давтахгүйгээр өөр өөр оролтын утгуудаар шалгах боломжтой болсон.

Лабораторийн ажлын явцад нийт **39 test case** ажиллуулж, эхний хэсэгт бүх тест амжилттай болж, mvn-test.txt файл руу хадгалсан.

```text
Tests run: 39, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

## Mutation Testing

'GradeCalculatorTest.java' дотор бичигдсэн тестүүд зөвхөн зөв ажиллаж байгааг шалгахаас гадна шаардлагатай алдааг илрүүлж чадаж байгаа эсэхийг шалгахын тулд mutation testing хийсэн. Үүний тулд `GradeCalculator` классын `if (score >= 90)` гэсэн нөхцөлийг түр хугацаанд `if (score > 90)` буюу "90-с их ба тэнцүү"-г зөвхөн "90-с их" байхаар болгон өөрчилсөн. Энэ хэсгийн тэнцүү тэмдгийг хассаны дараа 90 гэсэн оноо оруулахад A биш B болж үсгэн үнэлгээг буруу тооцсон. Boundary test-ийн 90 онооны тест энэ өөрчлөлтийг илрүүлж, тест амжилтгүй болсон.

```text
Tests run: 39, Failures: 1, Errors: 0, Skipped: 0
BUILD FAILURE
```

Алдааны хэсэгт:

```text
expected: <A> but was: <B>
```

гэж гарсан. Энэ нь 90 гэсэн зааг утгыг тестүүд зөв шалгаж байгааг харуулсан. Mutation test дууссаны дараа кодын нөхцөлийг буцааж `score >= 90` болгож, бүх тестийг дахин ажиллуулахад 39 тест бүгд амжилттай болсон.

## Test ажиллуулах

```bash
mvn clean test
```

Үр дүнг `results/mvn-test.txt` файлд хадгалсан.

Mutation test-ийн үр дүнг:

```text
results/mvn-test-mutant.txt
```

файлд хадгалсан.

## Нэмэлт даалгавар – AI өнцөг

Нэмэлт даалгаврын хүрээнд `GradeCalculator` классын шаардлагыг AI туслахад (Chatgpt) өгч, unit test-ийн жишээ тестүүдийг гаргуулж үзсэн. AI нь тестийн үндсэн хэсэг болох үсгэн дүнг ангилах, зөвшөөрөгдөх онооны хязгаар, буруу утга гарах үед exception шалгах гэх мэт тестүүдийг гаргасан. Харин эхний хувилбарт лабораторийн ажлын заавар дээр зөвлөсөн 90, 89.99, 60, 59.99 зэрэг зааг утгуудыг онцлон шалгах шаардлагыг гаргаагүй тул эдгээрийг өөрөө нэмж шалгасан. Мөн `totalScore` method-ийн бүх оролтын дээд болон доод хязгаарыг тус тусад нь шалгах нь чухал гэдгийг тестийн шаардлагатай харьцуулж баталгаажуулсан. AI-ийн санал болгосон энгийн зөв утгын тестүүд хэрэгтэй байсан боловч ижил утгыг давтан шалгасан зарим тестүүд нэмэлт ач холбогдол багатай байсан. Харин `assertThrows` ашигласан буруу утгын тест болон boundary value test-үүд нь бодит алдааг илрүүлэх боломжтой учраас илүү чанартай гэж үзсэн. Иймээс AI-ийн гаргаж өгсөн тестүүд нь анзаараагүй үлдээсэн тохиолдлыг олоход хэрэгтэй байсан ч эцсийн тестүүдийг лабораторийн шаардлага болон зайлшгүй шалгах шаардлагатай хэсгүүдийг нэмэлтээр бичиж оруулсан.

## Дүгнэлт

Энэ лабораторийн ажлаар JUnit 5 ашиглан unit test бичих үндсэн аргачлалтай танилцсан. Лабораторийн ажлын зааврын дагуу `GradeCalculator` классын үйлдлүүдийг олон төрлийн оролтын утгаар шалгасан. Тестүүдээ бичихдээ Arrange, Act, Assert бүтэц болон boundary value testing аргыг ашиглаж, ялангуяа зааг утгууд болох 90, 90.99, 59.99 гэх мэт үнэлгээн дээр гарч болох алдааг шалгасан. Мөн буруу утга буюу 100-с дээш эсвэл 0-с доош үнэлгээ оруулах үед `assertThrows` ашиглан `IllegalArgumentException` гарч байгаа эсэхийг шалгаж, баталгаажуулсан. `@ParameterizedTest` болон `@CsvSource` ашигласнаар олон төрлийн өгөгдлийг давхар код бичихгүйгээр шалгах боломжтой болсон. Mutation testing хийх явцад 90 онооны нөхцөлийг өөрчлөхөд (if (score >= 90 хэсгийг score > 90 болгож өөрчилсөн)) тест тухайн хэсгийн алдааг илрүүлж чадсан (90 гэсэн үнэлгээг оруулахад A биш B үсгэн үнэлгээ гаргасан) нь boundary test-ийн давуу талыг харж, дараа дараагийн удаа хэрэгжүүлэх нь тестийг илүү үр ашигтай болгох боломжтойг ойлголоо. Мөн Maven болон Java compiler-ийн тохиргооноос үүссэн `source 7` алдааг засаж, төслийг Java 17 орчинд амжилттай ажиллуулсан. Эхний байдлаар 39 тестийг ажиллуулж, 'BUILD SUCCESS' үр дүн гарсан. Дараагийн удаа mutation test-ийн хэсгийг 'GradeCalculator.java' файл дотор өөрчлөлт хийсний дараа ажиллуулснаар 38 тест амжилттай, 1 тест failure болсон тул `BUILD FAILURE` үр дүн авсан. Тухайн тестийн хариунуудыг 'results' хавтас дотор txt файл хэлбэрээр оруулж, github руу эцсийн байдлаар 'push' хийж, баталгаажууллаа. Энэ ажлаар зөвхөн код ажиллаж байгаа эсэхийг шалгахаас гадна кодын ажиллагааг тестийн тусламжтай илүү нарийн алдааг нь илрүүлэх боломжтойг, мөн ирээдүйд үүсч болох алдаа, эрсдэлийг урьдчилан шалгах тест бичих нь ямар чухал ач холбогдолтойг мэдлээ.
